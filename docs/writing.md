# 写一篇新文章

写文章只需要在 `src/content/posts/` 里加一个 Markdown 文件，其他地方都不用动。构建时，首页的格子、文章抽屉、归档、分类和标签页、全站搜索、RSS 都会自动带上这篇。

下面按顺序走一遍，最后附一篇年终总结的完整例子。

## 1. 新建文件

文件名固定写成 `年-月-日-名字.md`：

```
src/content/posts/2026-12-31-2026-年终总结.md
```

这个文件名决定文章的地址，上面这篇的地址是 `/2026/12/31/2026-年终总结/`。名字部分可以用中文，词和词之间用 `-` 连。不要用空格，也不要用 `?`、`#`、`/`，这些字符在地址里有特殊含义。

日期一定要写全成 `2026-12-31` 这样，月和日不够两位要补 0，不然算不出地址。

## 2. 写文件头

文件开头两行 `---` 之间是文章信息：

```yaml
---
title: "2026 年终总结"
description: "一句话摘要"
date: 2026-12-31T20:00:00+08:00
category: "随笔"
tags: ["年终总结", "成长"]
---
```

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `title` | 是 | 文章标题 |
| `description` | 否 | 一句话摘要，用在文章列表、搜索结果、RSS 和搜索引擎摘要里 |
| `date` | 是 | 发布时间，文章按它排序 |
| `updated` | 否 | 更新时间，写了文章页会显示"更新于" |
| `category` | 否 | 分类，一篇只能有一个，不写默认是"随笔" |
| `tags` | 否 | 标签，可以有多个，必须写成 `["a", "b"]` 这样的数组 |
| `series` | 否 | 系列名，同名的文章在开头互相串起来 |
| `draft` | 否 | 写 `true` 就是草稿，只在本地预览时显示，不会发布 |

时间后面的 `+08:00` 是时区，写北京时间就保留它。文件名里的日期只管地址，排序看的是 `date`，两边写成同一天最不容易乱。

分类和标签写新的就会自动出现新的分类页和标签页，不用提前建。同一个意思尽量沿用已有的写法，比如已经有了 `Spring Boot`，就不要再写 `SpringBoot`，否则会变成两个标签。名字里同样不要带 `/`。

`series` 适合连载或每年都写的文章。几篇文章写同一个系列名，文章开头就会出现"系列 · 名字 · 2/3"这样的导航，按 `date` 排序。只有一篇的系列不显示导航。

## 3. 写正文

文件头下面就是普通 Markdown。几个和这个主题有关的地方：

**标题和目录。** 用 `##` 写小节标题，它们会进入文章页的目录。至少三个 `##` 才会显示目录，宽屏时目录在左边，窄屏时在正文上方可以展开。`###` 不进目录。正文里不要再写 `#` 一级标题，页面顶上已经用 `title` 显示过了。

**代码块。** 在三个反引号后面写上语言名，比如 ` ```java `、` ```bash `，才会有语法高亮。每个代码块右上角会自动出现 copy 按钮，放不下的长代码还有 wrap 按钮，可以在横向滚动和自动换行之间切换。

**图片。** 图片放进 `public/` 目录，建议每篇一个文件夹，比如 `public/images/2026-summary/a.jpg`，正文里写：

```markdown
![图片说明](/images/2026-summary/a.jpg)
```

路径以 `/` 开头，不要写 `public`。图片说明会在图片加载不出来时显示，也方便读屏软件，最好认真写一句。

**阅读时间。** 文章页显示的"约 N 分钟"是自动算的，按每分钟 300 字，代码块不算在内，不用自己写。

加粗、链接、表格、引用、列表都按标准 Markdown 写。

## 4. 本地预览

```bash
npm run dev
```

打开 http://localhost:4321 ，保存文件后页面会自动刷新。草稿在这里也能看到。

发布前建议再跑一次 `npm run build`。文件头写错时，构建会报错并写出是哪个文件，这一步过了，推送上去也就能过。

## 5. 发布

确认写完后，删掉 `draft: true` 这一行（或改成 `false`），然后推送：

```bash
git add src/content/posts public
git commit -m "新文章：2026 年终总结"
git push
```

推送到 `main` 后，GitHub Actions 会自动构建和发布，一两分钟后就能在网站上看到。进度可以在仓库的 Actions 页面查看。

还没写完的文章也可以带着 `draft: true` 先推送上去，不会出现在网站上。

## 6. 之后修改或删除

改错别字之类的小修改，直接改文件再推送即可。内容有较大变化时，加一行 `updated`：

```yaml
updated: 2027-01-05T10:00:00+08:00
```

文章页会显示更新日期。一年多没更新的文章，开头会自动提示内容可能过时，`updated` 也会重新计算这个时间。

不要改已发布文章的文件名，地址会跟着变，别人收藏的链接和评论都会对不上。要下线一篇文章，删掉文件或者改回 `draft: true` 都可以。

## 完整例子：年终总结

文件 `src/content/posts/2026-12-31-2026-年终总结.md`：

```markdown
---
title: "2026 年终总结：换了方向的一年"
description: "这一年做了什么、学到了什么，明年想怎么过。"
date: 2026-12-31T20:00:00+08:00
category: "随笔"
tags: ["年终总结", "成长"]
series: "年终总结"
draft: true
---

开头一两段，说说这一年整体的感受。

## 工作

## 学习

![今年读完的书](/images/2026-summary/books.jpg)

## 生活

## 明年
```

`category` 和 `tags` 沿用了 `2025-12-30-2025-年终总结.md` 的写法，两篇会出现在同一个分类和标签页里，文末的"相关文章"也会互相推荐。再在 2025 那篇的文件头里也加上 `series: "年终总结"`，两篇开头就会出现系列导航，以后每年的总结都能串起来。

## 常见报错

**构建报错指向文件头。** 检查这几处：`date` 是不是 `2026-12-31T20:00:00+08:00` 这种格式；`tags` 有没有写成数组；冒号后面有没有空格；标题里有英文双引号时，外面改用单引号包起来。

**文章没出现在网站上。** 看看是不是还留着 `draft: true`，或者 Actions 页面里这次发布有没有失败。

**图片不显示。** 确认图片在 `public/` 下面，路径以 `/` 开头且没有写 `public`，文件名的大小写和正文里一致。GitHub Pages 区分大小写，本地正常、上线后图片不显示，多半是这个原因。
