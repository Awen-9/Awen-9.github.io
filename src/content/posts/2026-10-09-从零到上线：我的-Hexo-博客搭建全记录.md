博客今天算是正式上线了。从晚上坐下折腾到凌晨，中间推翻重来好几次，趁记忆还热乎，把整个过程记下来。

## 为什么是 Hexo

其实纠结过很久。Notion 最省事，WordPress 最省心，但想来想去还是想要一个自己的地方——数据是自己的 Markdown 文件，服务器不用管，钱也不用花。GitHub Pages 托管静态页面，Hexo 生成，这套组合虽然老，但老的东西有个好处：坑都被前人踩完了。

动手之前的环境就两样，Node 和 Git，都不用额外装什么。

## 初始化：十分钟的快感

Hexo 的初始化快得让人怀疑人生：

```bash
npm install -g hexo-cli
hexo init my-blog
cd my-blog
hexo server
```

`localhost:4000` 打开，一个博客就出现了。当然，出现的是官方默认主题 landscape，丑得很稳定。这时候改改 `_config.yml` 里的标题、作者、语言，算是有了个壳子。

结构上值得留意的就几个地方：`source/_posts` 放文章，`themes` 放主题，`_config.yml` 是站点配置。`public` 目录是构建产物，每次 `hexo generate` 都会重新生成，不用手动碰。

## 主题：先用别人的，再自己写

一开始我选了个人气很高的主题，中文社区里很有名，功能全到离谱——动画、侧栏、音乐播放器、看板娘。装上之后看着确实漂亮，但很快就不对劲了：配置文件一千多行，我只想改个边距，得先在文档里考古半天；构建出来的东西也重，九成的功能我根本用不上。

后来干脆把 GitHub 上的极简主题翻了个遍，SoSimple、Cactus、Even 这些都点开 demo 看过。看多了反而想明白一件事：这些主题拆开看，核心就是几个 EJS 模板加一份 CSS，没什么魔法。那就自己写吧。

主题的目录结构长这样：

```
themes/my-theme/
├── _config.yml
├── layout/
│   ├── layout.ejs        # 所有页面的外壳
│   ├── index.ejs         # 首页文章列表
│   ├── post.ejs          # 文章页
│   ├── archive.ejs       # 归档
│   └── partial/          # 头部、页脚、分页这些复用件
└── source/
    ├── css/style.css     # 灵魂所在
    ├── js/main.js
    └── img/favicon.svg
```

Hexo 干的事就是把你的 Markdown 塞进这些模板里。比如首页就是把文章循环一遍：

```
<% page.posts.each(function (post) { %>
<article class="post-item">
  <span class="post-date"><%= date(post.date, 'MM-DD') %></span>
  <a class="post-title" href="<%- url_for(post.path) %>"><%= post.title %></a>
</article>
<% }) %>
```

注意 EJS 里 `<%= %>` 是转义输出，`<%- %>` 是原样输出，渲染 HTML 必须用后者，这个坑第一个晚上就踩了。

样式上我给自己立了三条规矩：单栏 720px 居中，留白管够；全站只有一个点缀色（选了青蓝，具体为什么，大概凌晨两点的人做决定都比较果断）；标题用衬线的霞鹜文楷，正文用系统黑体，两种字体气质拉开就够了。

明暗模式用 CSS 变量做的，颜色全部抽成变量，切换时只改变量值：

```css
:root        { --bg: #fcfcfa; --text: #2c2c2a; --accent: #3a7ca5; }
[data-theme="dark"] { --bg: #1c1e22; --text: #d8d6d0; --accent: #7fb3d5; }
```

JS 只有一小段，放在 `<head>` 里，进页面之前先读 localStorage，不然暗色模式下刷新会白屏闪一下，很难受。

## 部署：这一步坑最多

部署本身不复杂，复杂的是前置条件。

先装插件：

```bash
npm install hexo-deployer-git --save
```

然后建仓库。这里我犯了个很蠢的错误——仓库名写成了 `.github.io`，把用户名前缀给漏了。GitHub Pages 只认 `<用户名>.github.io` 这种格式，差一个字都不行，它直接不认。后来去仓库 Settings 里改名才解决。

`_config.yml` 里的部署配置：

```yaml
deploy:
  type: git
  repo: https://github.com/你的用户名/你的用户名.github.io.git
  branch: main
  name: 你的用户名
  email: 你的noreply邮箱
```

重点说 `name` 和 `email` 这两项。我一开始没配，部署完去 GitHub 上看提交记录，提交人是我电脑的账户名，邮箱是个本机名拼出来的假地址——因为这台机器从没配置过全局 git 身份，git 找不到就自己回退了一个，非常尴尬。解决方式要么配全局，要么像上面这样只在部署配置里指定。邮箱建议用 GitHub 的 noreply 地址，在 Settings → Emails 页面能查到，既不暴露真实邮箱，提交又能正确挂到自己账号上。

然后是凭据。GitHub 早就不能拿密码推代码了，需要 Personal Access Token，在 Settings → Developer settings 里生成，勾 repo 权限。我用钥匙串存凭据，配好之后 push 就不用再输了：

```bash
git config --global credential.helper osxkeychain
```

一切就绪，三连：

```bash
hexo clean
hexo generate
hexo deploy
```

deploy 做的事其实就是把 `public/` 目录当个 git 仓库强推到远端 main 分支，GitHub 那边检测到内容自动构建。我这次等了不到一分钟，`https://用户名.github.io` 就能访问了，还挺神奇的。

## 上线后的几件小事

RSS 和 sitemap 各需要一个插件，`hexo-generator-feed` 和 `hexo-generator-sitemap`，装上之后在配置里加几行，重新 generate 就会多出 `atom.xml` 和 `sitemap.xml`。前者给用订阅器的读者，后者给搜索引擎。

404 页面就是在 `source/` 下放一个 `404.html`，GitHub Pages 会自动用。文章页的代码块复制按钮是十几行 JS：遍历代码块，追加个按钮，点击调 `navigator.clipboard.writeText`。写技术博客这个功能迟早要加，不如一开始就加上。

## 之后的日常

现在写一篇文章的完整流程：

```bash
hexo new "文章标题"
# 编辑 source/_posts/ 里刚生成的文件
hexo clean && hexo deploy
```

不到一分钟，线上就有了。

回过头看，这一晚上最大的收获其实不是博客，是把静态站的整条链路过了一遍：模板、CSS 变量、git 凭据、Pages 构建。博客里放什么内容还没完全想好，但至少——地方是自己的了。
